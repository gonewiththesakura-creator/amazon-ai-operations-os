# M1.7 Information Architecture and Progressive Disclosure

## Outcome

M1.7 restructures the implemented M1.6 workspace into an executive-first operating flow without changing the API, PostgreSQL schema, `HomeComposition` response, synthetic runtime, or Zen Executive visual tokens.

The frontend now owns a deterministic presentation boundary:

`HomeComposition -> buildHomeViewModel() -> registered React components`

No model output can create arbitrary HTML, JavaScript, CSS, component identifiers, or evidence.

## Four Disclosure Layers

1. Executive layer: one operating judgment, one-line context, no more than four stage-aware metrics, and no more than three ranked actions.
2. Operating-domain layer: six fixed rows for sales and conversion, advertising, product and listing, inventory and profit, search ranking, and market opportunity.
3. Detail layer: M1.8 supersedes the former two-domain automatic rule. One priority domain auto-expands; a user may keep at most two open. Each expanded domain displays bounded registered content.
4. Evidence layer: provenance, raw references, attribution limitations, confidence details, and machine-oriented context are available through Inspector only.

Full conversation history is separated into a drawer. The home canvas retains only the latest compact Jarvis response so operational analysis remains primary.

## Presentation Contracts

The mapping is implemented in:

- `apps/web/view-models/home.ts`
- `apps/web/view-models/operating-domains.ts`
- `apps/web/components/OperatingDomains.tsx`

The fixed domain identifiers are:

- `SALES_CONVERSION`
- `ADVERTISING`
- `PRODUCT_LISTING`
- `INVENTORY_PROFIT`
- `SEARCH_RANKING`
- `MARKET_OPPORTUNITY`

Priority actions, follow-up questions, approval requests, executive summaries, critical alerts, top metric strips, and generic data tables are not duplicated as domain detail blocks. Unknown or unsupported registered blocks fail visibly while their references remain available in Inspector.

## Responsive Order

On narrow screens, the reading order is fixed:

1. Today judgment
2. Summary metrics
3. Priority actions
4. Operating domains
5. State-aware questions
6. Latest Jarvis response

The persistent composer remains accessible without changing this document order. Navigation, Inspector, settings, approvals, and conversation history use keyboard-safe drawers.

## Boundaries

- All demo values remain `synthetic=true`.
- The MVP remains read-only and exposes no Amazon write operation.
- M1.7 does not add or modify database migrations.
- M1.7 does not change the `HomeComposition` schema or API behavior.
- M1.7 does not alter the approved M1.6 color, typography, radius, spacing, or theme semantics.
