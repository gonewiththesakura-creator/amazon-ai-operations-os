# M1.8 Visual Analytics Layer

## Outcome

M1.8 adds a deterministic visualization path without changing `HomeComposition` or allowing Jarvis to invent numerical data:

`PostgreSQL -> get_metric_series / get_top_entities / get_mix_breakdown -> GET /v1/visualizations/home -> visualization view model -> registered native SVG components`

Every artifact carries evidence references, source, period, update time, confidence, limitations, and `synthetic`. Missing PostgreSQL rows are omitted. The browser never fills gaps with zeroes or generates plausible history from scalar metrics.

## Presentation Contract

- Summary metrics may use a seven-day sparkline only when an explicit source series exists.
- Exactly one domain auto-expands: highest-priority `CRITICAL`, then `ATTENTION`, then `SALES_CONVERSION`.
- Users may keep at most two domains open; collapsed domains expose no more than two metrics.
- Expanded domains render at most one primary visualization, one secondary visualization, one Jarvis insight, and one evidence action.
- Sales selectors are Orders, Sales, CVR, and Sessions when those series exist.
- Advertising selectors are ACOS, Spend, CPC, CTR, and CVR when those series exist.
- A donut requires meaningful part-to-whole data and at most five slices; excess source categories become `Other` in the deterministic layer.
- Inventory coverage uses progress or horizontal bars. Contribution profit uses a line. Ranking uses one inverted-Y keyword line only when that grain exists.
- Product/Listing and Market/Opportunity retain registered-list or narrative fallbacks when no valid time series exists.

Heavy domain analytics use `next/dynamic` and mount only inside expanded content. Charts use transparent canvases, ZEN EXECUTIVE tokens, 11px minimum text, keyboard-focusable points, descriptive SVG labels, and a written source state in tooltips. Reduced motion removes reveal animations but not data.

## Tool Bounds

`get_metric_series` accepts a store-scoped metric and 1-90 day lookback. M1.8 implements orders, sales, sessions, CVR, ad spend, ad sales, ACOS, CPC, and CTR.

`get_top_entities` ranks 1-5 ASINs for orders, sales, or sessions. `get_mix_breakdown` returns orders or sales by ASIN with 2-5 slices. No Campaign or search-term chart is exposed because the current PostgreSQL schema does not hold that source grain.

All three tools are read-only, tenant-scoped, schema-validated, and audit logged through Tool Gateway. No Amazon write tool exists.

## State Semantics

- HomeComposition request failure: explicit Home API error.
- Valid composition without metrics, actions, or mapped operating signals: explicit empty Home state.
- Optional visualization request failure: the Home remains usable and falls back to registered narrative/detail content.
- Missing or invalid visualization source: omit the chart; never fabricate a placeholder trend.

## Acceptance Evidence

Automated web coverage includes `visualization-view-model.test.ts`, `sparkline.test.tsx`, `domain-charts.test.tsx`, and `chart-progressive-disclosure.test.tsx`. Backend coverage verifies input bounds, tool permissions, evidence envelopes, missing-data omission, tenant filters, and the visualization endpoint. Full acceptance requires web typecheck/test/build, API and infrastructure suites, plus desktop and mobile browser inspection.
